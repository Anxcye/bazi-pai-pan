# 排盘规则规格书

## 文件作用

- 定义本项目“八字排盘”功能的统一计算口径。
- 作为前端实现、测试用例设计、后续规则扩展的唯一基准。

## 系统位置

- 建议路径：`docs/PAIPAN_SPEC.md`

## 关联模块

- 上游：`features/input`（用户出生信息录入）
- 核心依赖：`domain/calendar`、`domain/bazi`
- 下游：`features/chart`、`storage`、测试用例、解释层

## 目标

本规格书用于明确：
- 输入项
- 时间标准化规则
- 年柱、月柱、日柱、时柱的确定方式
- 大运等扩展功能的计算口径
- 边界情况与争议点处理

本项目目标是做“专业口径、工程可实现、结果可测试”的排盘系统。

---

## 1. 版本与口径

### 1.1 默认口径（V1）

V1 默认采用以下规则：
- 年柱：以立春切换年柱
- 月柱：以二十四节气中的“节”切换月柱
- 日柱：以本地标准时间 00:00 切换日期
- 时柱：按标准十二时辰划分
- 时区：严格按输入时区换算本地出生时间
- 真太阳时：默认关闭
- 早晚子时：默认关闭
- 农历输入：允许输入，但内部统一转换为公历时间后再排盘

### 1.2 高级口径（预留）

后续可通过高级设置切换：
- 子时换日口径：
  - 00:00 换日（默认）
  - 23:00 换日
  - 早晚子时
- 真太阳时：
  - 关闭（默认）
  - 开启
- 起运算法：
  - 按常见节令差换算
  - 其他流派扩展

## 2. 输入规格

## 2.1 必填输入

### 基础排盘必填
- 出生日期：年、月、日
- 出生时间：时、分
- 时间制：默认 24 小时制
- 时区：IANA 时区字符串，例如 `Asia/Shanghai`
- 性别：男 / 女 / 其他
- 历法类型：公历 / 农历

### 说明
- 若用户只提供“某时辰”而无具体分钟，系统应允许录入并标记精度等级。
- 若用户只知道日期、不知道时间，可允许“未知时辰”模式，但该模式不能输出时柱，且提示结果不完整。

## 2.2 可选输入

- 出生地
  - 用途：真太阳时计算、展示、资料保存
  - 内容：国家 / 省 / 市 / 经纬度（后端或地理服务可补全）
- 是否启用真太阳时
- 子时换日规则
- 夏令时修正开关（高级）
- 备注 / 标签 / 用户姓名

## 2.3 内部标准化输入模型

```ts
interface BirthInput {
  calendarType: 'solar' | 'lunar'
  birthDate: string            // YYYY-MM-DD
  birthTime: string | null     // HH:mm
  timezone: string             // e.g. Asia/Shanghai
  gender: 'male' | 'female' | 'other'
  birthPlace?: string
  longitude?: number
  latitude?: number
  useTrueSolarTime?: boolean
  dayBoundaryRule?: 'midnight' | 'zi-hour' | 'split-zi-hour'
  isDstAware?: boolean
  note?: string
}
```

## 3. 时间标准化规则

## 3.1 标准化流程

无论用户输入公历还是农历，内部统一走以下流程：
1. 解析原始输入
2. 若为农历输入，先转换为对应公历日期时间
3. 结合输入时区得到“出生地本地标准时间”
4. 若启用真太阳时，则根据经度对时间进行修正
5. 根据标准化后的时间计算四柱

## 3.2 时区规则

- 不允许写死北京时间。
- 必须以用户选择的时区为准。
- 若用户未选时区：
  - 中国大陆默认 `Asia/Shanghai`
  - 非大陆用户必须显式提示确认

## 3.3 夏令时规则

- 对存在 DST 的地区，应尽量按时区数据库还原当时合法本地时间。
- 若某个本地时间因夏令时跳变而不存在，应提示用户校正。
- MVP 若不完整支持 DST，也必须在文档与 UI 中说明限制。

## 3.4 真太阳时规则

默认关闭。

当开启真太阳时时：
- 以出生地经度相对时区中央经线进行地方平太阳时修正
- 有条件时再叠加时间方程修正，得到真太阳时
- 若无经度数据，则不能启用真太阳时

建议：
- MVP 只提供“地方平太阳时”或直接不开放真太阳时
- 真太阳时作为高级功能，必须附带规则说明

## 4. 四柱计算规则

## 4.1 年柱

### 默认规则
- 以“立春”作为年柱切换点
- 出生时刻在该年立春之前，则年柱仍属上一干支年
- 出生时刻在该年立春及之后，则进入新干支年

### 说明
- 年柱不按农历正月初一切换
- 这是命理排盘的主流工程口径之一

### 示例
- 某年 2 月 4 日立春前出生：仍算上一年柱
- 立春后出生：切换到当年柱

## 4.2 月柱

### 默认规则
- 月柱按“节”切换，不按农历月份切换
- 十二个月柱对应十二个“节”起点：
  - 立春起寅月
  - 惊蛰起卯月
  - 清明起辰月
  - 立夏起巳月
  - 芒种起午月
  - 小暑起未月
  - 立秋起申月
  - 白露起酉月
  - 寒露起戌月
  - 立冬起亥月
  - 大雪起子月
  - 小寒起丑月

### 月干规则
- 月支固定按节令确定
- 月干依据“年上起月”规则推出：
  - 甲己之年丙作首
  - 乙庚之年戊为头
  - 丙辛之年庚作首
  - 丁壬之年壬为首
  - 戊癸之年甲作首
- 这里的“首”指寅月之天干，其余月份按天干顺推

### 说明
- 月柱必须按节气处理，这是专业排盘的核心要求
- 农历月份与节令月份并不完全一致，不能直接拿农历月代替月柱月支

## 4.3 日柱

### 默认规则
- 以标准化后的本地时间日期计算日干支
- 默认以 00:00 为换日点

### 日干支求法
工程实现可采用以下任一方式：
- 基于可靠历法库提供的干支日结果
- 基于儒略日与参考甲子日做推算

要求：
- 算法必须稳定
- 结果必须与选定基准库或样本表一致

## 4.4 时柱

### 时支规则
标准十二时辰映射如下：
- 子：23:00–00:59
- 丑：01:00–02:59
- 寅：03:00–04:59
- 卯：05:00–06:59
- 辰：07:00–08:59
- 巳：09:00–10:59
- 午：11:00–12:59
- 未：13:00–14:59
- 申：15:00–16:59
- 酉：17:00–18:59
- 戌：19:00–20:59
- 亥：21:00–22:59

### 时干规则
按“五鼠遁”由日干推出子时天干，再顺推各时辰：
- 甲己日：甲子时起
- 乙庚日：丙子时起
- 丙辛日：戊子时起
- 丁壬日：庚子时起
- 戊癸日：壬子时起

### 说明
- 时柱依赖日柱，因此子时换日口径会影响时柱

---

## 5. 子时换日规则

## 5.1 默认规则
- 默认使用 00:00 换日
- 即 23:00–23:59 仍属于当天，00:00 后属于次日

## 5.2 可选规则

### 规则 A：23:00 换日
- 23:00 起视为次日
- 整个子时归入次日

### 规则 B：早晚子时
- 23:00–23:59 为晚子时，日柱仍按前一日
- 00:00–00:59 为早子时，日柱按次日
- 时柱仍为子时

## 5.3 产品策略
- 默认只启用一种口径，避免普通用户混乱
- 高级设置中可切换，并在结果页标明当前口径
- 保存排盘结果时必须记录使用的换日规则

---

## 6. 农历输入规则

## 6.1 输入原则
- 用户可以输入农历年月日时
- 必须支持闰月标记
- 农历输入不直接决定月柱，只用于还原出生时刻

## 6.2 计算流程
- 先将农历日期转换为对应公历日期时间
- 再依据节气规则计算年柱/月柱

## 6.3 注意事项
- 农历月份与命理月柱不是同一概念
- UI 文案必须避免让用户误解为“农历几月就是几月柱” 

---

## 7. 藏干、十神、五行规则

## 7.1 藏干
- 每个地支按预定义藏干表映射
- 藏干顺序固定
- V1 不做流派差异配置

建议表：
- 子：癸
- 丑：己癸辛
- 寅：甲丙戊
- 卯：乙
- 辰：戊乙癸
- 巳：丙庚戊
- 午：丁己
- 未：己丁乙
- 申：庚壬戊
- 酉：辛
- 戌：戊辛丁
- 亥：壬甲

## 7.2 十神
- 以日干为“我”进行比较
- 按五行生克与阴阳同性/异性规则得到十神
- 需同时支持：
  - 天干十神
  - 藏干十神

## 7.3 五行
- 至少提供以下两类统计：
  - 显性五行：四柱天干地支对应五行计数
  - 含藏干五行：含支藏干后的五行计数
- V1 不做“旺衰强弱评分”的强结论，只做原始分布展示

---

## 8. 纳音、神煞、十二长生

## 8.1 纳音
- 可在 V1.1 加入
- 通过六十甲子查表得到

## 8.2 神煞
- 不纳入 V1 强依赖
- 因流派差异较大，作为可插拔扩展处理

## 8.3 十二长生
- 可在增强阶段加入
- 规则需与十神模块解耦

---

## 9. 大运规则

## 9.1 是否纳入 MVP
- 若项目定位“专业排盘”，建议纳入基础大运
- 但流年、流月可以后置

## 9.2 顺逆规则
主流规则之一：
- 阳男阴女顺排
- 阴男阳女逆排

其中：
- 阳 / 阴：通常指年干阴阳
- 男 / 女：指生理性别输入项或用户指定口径

实现时必须把“依据年干阴阳”写死到规格中，不要模糊。

## 9.3 起运时间
主流工程口径建议：
- 以出生时刻到最近节令之间的时间差换算起运岁数
- 顺排者取出生后至下一节
- 逆排者取出生前至上一节
- 按“三天一岁”换算
- 余数再换算月、日

## 9.4 输出格式
建议输出：
- 起运年龄（岁、月）
- 起运公历日期
- 每步大运干支
- 每步大运起止年份

## 9.5 风险
- 起运算法流派差异较大
- 必须在结果中注明当前算法口径

## 10. 流年、流月、流日、流时

项目既然定位专业排盘，增强版必须支持“四运并临”的动态时间层：
- 大运
- 流年
- 流月
- 流日
- 流时

这些层不是独立计算体系，而是在统一时间规则之上逐层展开。

## 10.1 统一原则

- 所有流转层都必须沿用同一套基础历法口径
- 流年按立春切换年柱
- 流月按节气中的“节”切换月柱
- 流日按选定换日规则切换
- 流时按十二时辰切换
- 若本命盘启用了真太阳时，则动态层默认继续沿用同一时间规则，除非产品明确允许仅本命启用

## 10.2 流年

### 定义
- 流年是目标年份在命理体系中的年度干支
- 不是简单公历 1 月 1 日换年

### 规则
- 以目标年份的立春作为流年切换点
- 立春前仍属上一流年干支
- 立春后进入新流年干支

### 输出建议

```ts
interface LiuNianItem {
  year: number
  ganzhi: string
  startAt: string
  endAt: string
}
```

### 说明
- 当用户查看某一公历年份时，UI 必须说明该年流年并非从 1 月 1 日开始
- 若要生成某时间区间的流年列表，应以立春为边界逐年生成

## 10.3 流月

### 定义
- 流月是目标流年内部按节令划分的十二个月柱

### 规则
- 与本命月柱同理，按“节”切换
- 月支固定从寅月开始轮转
- 流月天干根据流年天干按“年上起月”规则推出

### 十二流月起点
- 立春起寅月
- 惊蛰起卯月
- 清明起辰月
- 立夏起巳月
- 芒种起午月
- 小暑起未月
- 立秋起申月
- 白露起酉月
- 寒露起戌月
- 立冬起亥月
- 大雪起子月
- 小寒起丑月

### 输出建议

```ts
interface LiuYueItem {
  year: number
  monthIndex: number
  ganzhi: string
  jieqi: string
  startAt: string
  endAt: string
}
```

## 10.4 流日

### 定义
- 流日是目标时间线上的每日干支

### 规则
- 按统一换日规则递进
- 默认 00:00 换日
- 若启用 23:00 换日或早晚子时，则流日切换也必须同步遵循

### 工程实现建议
- 基于干支日连续序列推算
- 任意时刻先归属到命理意义上的“那一天”，再得到当日干支

### 输出建议

```ts
interface LiuRiItem {
  date: string
  ganzhi: string
  startAt: string
  endAt: string
}
```

## 10.5 流时

### 定义
- 流时是某一流日内按十二时辰推进的时柱

### 规则
- 时支按固定时辰表
- 时干按当日天干通过五鼠遁推出
- 因为流时依赖流日，所以一旦换日规则不同，23:00 之后的流时归属也会不同

### 输出建议

```ts
interface LiuShiItem {
  dateTime: string
  hourBranch: string
  ganzhi: string
  startAt: string
  endAt: string
}
```

## 10.6 大运、流年、流月、流日、流时的组合关系

专业排盘里常见的是把多个时间层叠加展示：
- 本命四柱
- 大运
- 流年
- 流月
- 流日
- 流时

因此结果模型建议允许同屏输出：

```ts
interface RuntimeLayers {
  dayun?: { ganzhi: string; startAge: number; startDate?: string }
  liunian?: { year: number; ganzhi: string }
  liuyue?: { label: string; ganzhi: string; jieqi: string }
  liuri?: { date: string; ganzhi: string }
  liushi?: { dateTime: string; ganzhi: string }
}
```

## 10.7 专业显示要求

若系统支持流转层，结果页建议明确分栏：
- 本命
- 运
- 年
- 月
- 日
- 时

并确保每一层都能展示：
- 干支
- 十神（相对于日主）
- 藏干
- 纳音（可选）
- 与本命/当前层的合冲刑害破关系（增强）

## 10.8 专业关系分析预留

在专业版中，动态层至少应预留以下分析接口：
- 大运与本命关系
- 流年与本命关系
- 流月与流年关系
- 流日与本命 / 流月 / 流年关系
- 流时与流日关系

建议不要把这些关系写死在 UI 层，而是由领域层产出结构化关系数据。

示例：

```ts
interface RelationHit {
  type: 'he' | 'chong' | 'xing' | 'hai' | 'po' | 'sheng' | 'ke' | 'tonghe'
  from: string
  to: string
  targetLayer: 'natal' | 'dayun' | 'liunian' | 'liuyue' | 'liuri' | 'liushi'
  note?: string
}
```

## 10.9 查询模式建议

系统应支持至少两种查询模式：

### 模式 A：当前时刻查询
- 用户选择一个具体时间点
- 系统返回该时刻对应的大运、流年、流月、流日、流时

### 模式 B：区间浏览
- 用户选择一个年份/月范围
- 系统按列表或时间轴返回该区间内的流年/月/日/时数据

### 模式 C：专业择时模式（后续）
- 用户指定某天或某区间
- 系统扫描流时，供后续择日择时功能使用

## 10.10 性能要求

因为流日、流时展开量很大，前端实现必须注意：
- 默认不要一次性展开过长区间的流时
- 月视图按需生成流日
- 日视图按需生成流时
- 使用 memoization / 缓存减少重复节气与干支计算

## 10.11 测试重点

动态层需要额外覆盖：
- 流年在立春前后切换是否正确
- 流月在每个“节”前后切换是否正确
- 流日在 23:00 / 00:00 边界是否与换日规则一致
- 流时在子时是否正确继承流日口径
- 本命盘与动态层在相同时刻下是否能保持统一规则

## 10.12 V1.5 建议结论

如果你要做“比较专业”的排盘，建议 V1.5 就把这些一起纳入设计：
- 本命四柱
- 基础大运
- 流年
- 流月
- 流日
- 流时

但交互上分阶段开放：
- 第一阶段先显示本命 + 大运 + 流年
- 第二阶段加入流月
- 第三阶段加入流日 / 流时与关系分析

## 12. UI 与文案要求

- 结果页必须显示当前排盘口径
- 若启用了真太阳时、早晚子时等高级规则，必须有明显标记
- 若用户只输入了日期没有具体时间，应提示“时柱未定，结果不完整”
- 若用户输入农历，应提示“月柱按节气计算，不等同于农历月”

## 13. 测试要求

## 13.1 测试分层

### 单元测试
- 干支推算
- 节气边界
- 月干推导
- 时干推导
- 藏干与十神映射

### 集成测试
- 输入 -> 标准化 -> 四柱 -> 大运 全链路

### 回归测试
- 建立一批人工校验样本
- 每次修改算法必须比对基准结果

## 13.2 重点测试场景

- 立春前后 1 分钟
- 各“节”前后 1 分钟
- 23:00 / 00:00 / 00:59 / 01:00
- 闰月农历输入
- 海外时区输入
- 启用 / 关闭真太阳时
- 顺排 / 逆排大运

## 13.3 样本策略

建议建立 3 类样本：
- 普通样本：常规白天出生
- 边界样本：节气临界点、子时临界点
- 特殊样本：闰月、海外、DST、真太阳时

## 15. 明确不做的事（V1）

V1 不默认承诺：
- 自动命理解读准确性
- 神煞大全
- 多流派自动混排
- 强行给出“喜用神”结论
- 所有民间口径兼容

V1 的目标是：
- 先把盘排准
- 规则透明
- 结果可复现
- 后续可扩展

---

## 16. 推荐的 V1 实施结论

如果项目要做“比较专业”的排盘，V1 建议固定如下：
- 支持公历/农历输入
- 内部统一标准化为本地公历时间
- 年柱按立春
- 月柱按节气之“节”
- 日柱默认 00:00 换日
- 时柱按标准时辰 + 五鼠遁
- 默认不启用真太阳时
- 支持大运基础版
- 所有结果记录当前规则版本

这套规则专业度足够高，也便于前端工程实现与测试。
